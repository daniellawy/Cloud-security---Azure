# 07 — Credential Access: Mimikatz Detection

## Objective

Investigate a Microsoft Defender XDR alert associated with suspected Mimikatz activity, identify the affected account and device, review the associated process and credential-access evidence, and use Advanced Hunting to investigate related activity.

## 1. Locate the Mimikatz Alert

Navigate to:

**Investigation & response → Incidents & alerts → Incidents**

Set the time range to **6 months**.

Locate the incident associated with the credential-theft investigation. Look for an alert identifying Mimikatz, credential dumping, or suspicious access to credential-related processes.

Open the alert page.

[Mimikatz incident](screenshots/01-mimikatz-incident.png)

## 2. Review Alert Context

Review the alert details to identify the entities and activity associated with the suspected credential-theft behavior.

The investigation reviewed:

- Affected device
- Associated user account
- Alert severity and timestamps
- Process and parent-process information
- Credential-access detection details

[Mimikatz alert](screenshots/02-mimikatz-alert.png)

## 3. Review the Alert Timeline

Open the **Alert timeline** and review the sequence of events associated with the detection.

Record the actual values displayed in the alert.

| **Field** | **Result** |
|---|---|
| Device | `<DEVICE_NAME>` |
| User | `<USER_ACCOUNT>` |
| Severity | `<ACTUAL_SEVERITY>` |

[Mimikatz alert timeline](screenshots/03-mimikatz-alert-timeline.png)

## 4. Review Process Execution Evidence

Open the process-related event associated with the alert.

Review the available process name, parent process, command-line context, timestamp, and related entities. Determine whether the evidence identifies Mimikatz directly or indicates behavior consistent with credential dumping.

The exact command line and sensitive execution details are not reproduced in this public documentation.

[Mimikatz process execution](screenshots/04-mimikatz-process-execution.png)

## 5. Review Credential-Access Evidence

Open the alert's evidence or investigation details.

Assess whether the alert identifies credential-access behavior, such as suspicious interaction with credential-bearing processes or memory. Distinguish observed evidence from the detection's assessment.

A Mimikatz-related alert is an investigative lead; validate the process evidence and surrounding activity before concluding that credentials were successfully extracted.

[Mimikatz credential-access evidence](screenshots/05-mimikatz-credential-access-evidence.png)

## 6. Review Response Actions

Review the response actions available for the affected device and account.

Depending on the incident and permissions, available actions may include:

- Run an antivirus scan
- Isolate the device
- Initiate an automated investigation
- Start a live response session
- Review or restrict application execution

Document only the actions actually performed. Do not imply that the device was isolated, credentials were reset, or remediation was completed unless this was verified.

[Mimikatz response actions](screenshots/06-mimikatz-response-actions.png)

## 7. Open Advanced Hunting

From the alert timeline, select **Go hunt** if the option is available.

Use Advanced Hunting to expand the investigation beyond the original alert. Examine activity around the alert timestamp and look for related process execution, account activity, and other events on the affected device.

[Advanced Hunting entry point](screenshots/07-mimikatz-go-hunt.png)

## 8. Run an Advanced Hunting Query

Use the query generated by Defender XDR or construct a query based on the tables available in your tenant.

For a Microsoft Defender XDR environment with `DeviceProcessEvents` available, the following query searches for process events containing Mimikatz-related names:

```kusto
DeviceProcessEvents
| where Timestamp >= ago(30d)
| where FileName has "mimikatz"
    or ProcessCommandLine has "mimikatz"
| project
    Timestamp,
    DeviceName,
    AccountName,
    FileName,
    ProcessCommandLine,
    InitiatingProcessFileName
| order by Timestamp desc
```

This is a name-based hunting query, not a comprehensive credential-dumping detector. It can miss renamed binaries and may return benign test or security-tool activity. The table and columns must be available in your Defender XDR Advanced Hunting environment; they are not confirmed as tables in your separate Azure Log Analytics workspace.

```text
        ↓

        ↓

```

## Result

The investigation reviewed a suspected Mimikatz-related credential-access alert in Microsoft Defender XDR. It focused on identifying the affected account and device, examining the alert timeline and process evidence, assessing the credential-access indicators, reviewing available response actions, and expanding the investigation through Advanced Hunting.

The final conclusion should state whether the evidence **confirmed Mimikatz execution, indicated suspicious credential-access behavior, or was inconclusive**. Document any containment or remediation only when supported by the investigation record.
